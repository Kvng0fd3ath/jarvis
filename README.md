# Zero

A minimal personal desk-companion desktop app starter. Electron provides the installer shell and signed-release updater; the UI is a local prototype with a small demo responder. It does **not** connect to an AI service or place phone calls yet.

## Run locally

```sh
npm install
npm start
```

## Build installers

```sh
npm run dist          # current platform
npm run dist:mac
npm run dist:win
npm run dist:linux
```

Installers are written to `release/`. Build each target on its supported OS (or use an appropriately configured CI runner). macOS distribution outside development needs Apple code signing and notarization; Windows distribution should be Authenticode-signed for a trustworthy install experience.

## Publish an update

The updater is wired to GitHub Releases for `Kvng0fd3ath/jarvis`. Bump `version` in `package.json`, then publish a GitHub release from a build machine with a `GH_TOKEN` that can create releases in that repository:

```sh
GH_TOKEN=... npm run publish
```

Do not paste tokens into source or commit them. Users need to have installed a packaged release first. `electron-updater` checks on launch and every six hours, downloads updates in the background, and installs a downloaded update when the app quits. macOS updates require a signed app; production releases should be signed on every platform.

## What is intentionally not wired yet

- **AI:** add a provider adapter in the main process. Keep API keys out of renderer code and use the OS credential store for any user secrets.
- **Calling:** add a telephony provider only if desired, with explicit opt-in, verified phone number, and an obvious disconnect control. This starter neither requests a number nor makes calls.
- **Real chat:** current replies are local demo text, not generated by an AI model.

## Security baseline

The renderer has context isolation and sandboxing enabled, no Node integration, a restrictive Content Security Policy, and only a small preload API for update status/actions. Keep privileged operations in the main process and expose narrowly scoped IPC methods.
